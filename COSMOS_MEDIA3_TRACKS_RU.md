# Cosmos — диагностика видеодорожек Media3

Это исследовательская сборка для ветки `develop`, не исправление видеоплеера.

- При открытии HTTP(S) потока Debug APK параллельно запускает **отдельный** Media3 ExoPlayer, который только выполняет `prepare()`, читает информацию о дорожках и завершает работу через 15 секунд. Он не вызывает `play()` и не занимает видеоповерхность.
- В `logcat` появляются строки `DCTV_TRACKS`: `group type=video`, `mime`, `codecs`, `resolution`, `supported`, `selected`, список видеодекодеров устройства; также ошибки подготовки и количество обнаруженных дорожек.
- Диагностический плеер создаёт **дополнительные сетевые обращения к источнику**. Не использовать на лимитированных или платных потоках. Адрес не записывается в журнал.
- Этот метод тестирует *отдельный* экземпляр ExoPlayer с тем же URL/headers; выбор дорожек основного плеера может отличаться. Для точной трассировки основного ExoPlayer потребуется инструментирование video_player_android.
- Диагностика компилируется только в Debug, Release APK не включает дополнительные зависимости.
- Debug-пакет `com.dreamcast.app.diagnostic` не перезаписывает стабильную v0.6.0.

## Как проверить
1. GitHub Desktop → `develop`, заменить содержимое проекта (исходники из корня ZIP).
2. Commit + Push и собрать Debug APK обычным Workflow.
3. Установить на Cosmos, открыть серию, подождать ~15 секунд.
4. Запустить на Windows PowerShell:

```powershell
& 'D:\adb\adb.exe' -s 192.168.0.9:5555 logcat -d -v threadtime | Select-String 'DCTV_TRACKS|DCTV_DIAG|ExoPlayerImpl|MediaCodec' | Out-File "$HOME\Desktop\cosmos-media3-tracks.txt" -Encoding utf8
```

Прикрепить `cosmos-media3-tracks.txt`. Если `group type=video` отсутствует — изучим manifest/URL, а если присутствует и не поддерживается — декодер или формат. Если выбран и поддерживается, необходима диагностика фактического видеорендера первого кадра.

**Не проверено сборкой Flutter/Gradle в этой среде.**
