# Dream Cast TV — правила для ИИ-агентов

Файл читают Codex (`AGENTS.md`) и Claude Code (через `CLAUDE.md`). Репозиторий
публичный: не добавляйте сюда адреса устройств, серийные номера, MAC-адреса,
ключи и личные данные — ни свои, ни пользователей.

## Проект

- Неофициальный клиент Dream Cast для Android TV / Google TV на Kotlin и
  Jetpack Compose (TV Material). Сборка — в `native-android/`, модуль `app`,
  плюс `baselineprofile` и `dav1d`.
- Пакет приложения — `com.dreamcast.app`, namespace кода —
  `com.dreamcast.nativeapp`. minSdk 23, target/compile 36, ABI armeabi-v7a и
  arm64-v8a.
- Плеер: Media3/ExoPlayer 1.11.1 и программный AV1 через dav1d
  (`Libdav1dVideoRenderer`, исходники готовит `scripts/prepare_media3_dav1d.py`).
- Сайт разбирается в `data/SiteClient.kt` и соседних файлах; запросы — только
  к хосту сайта.
- Язык общения с владельцем проекта, README и заметок к выпускам — русский.
  Сообщения коммитов — английский, Conventional Commits (`fix:`, `docs:`,
  `refactor:` …) с телом, объясняющим зачем.

## Сборка и тесты

- JDK 17. Локально он лежит в `.tools/jdk17/jdk-17.*` (папка `.tools/` в
  `.gitignore`); `ANDROID_HOME` — Android SDK, NDK `28.2.13676358`.
- Unit-тесты: `native-android/gradlew -p native-android :app:testDebugUnitTest`.
  Перед коммитом кода они должны проходить.
- Тестовая сборка рядом с установленным приложением:
  `-PnativeDebugSuffix=.имяТеста` (например `.decoderTest`) даёт отдельный
  пакет `com.dreamcast.app.имяТеста`. В PowerShell аргумент `-P…` берите в
  кавычки целиком.
- Файлы в репозитории — с окончаниями строк CRLF. Не превращайте их в LF при
  правке (sed и некоторые редакторы это делают).

## Ветки и выпуски

- Работа идёт в `develop`; в `main` — только через PR `develop → main`.
  Коммитить, пушить и открывать PR — только когда владелец явно попросил.
- Пуш в `develop` запускает `build-tv-apk.yml` (тесты, lint, debug и release
  APK). Выпуск собирает `build-tv-release.yml`, его запускают вручную на
  `main` после слияния PR.
- Номер выпуска — следующий после последнего тега `vX.Y.Z`
  (`scripts/app_version.py next`); Y и Z — от 0 до 9, после 0.9.9 идёт 1.0.0.
  versionCode = X·1 000 000 + Y·100 000 + Z·1000 + 1.
- Перед PR в `main` обязательно:
  - `docs/release-notes/RELEASE_NOTES_vX.Y.Z.md` для следующего номера — без
    него сборка выпуска падает;
  - в README раздел «Что нового в vX.Y.Z», ссылка на заметки и строка
    «Последний выпуск — **vX.Y.Z**».
- В заметки уже вышедшей версии не дописывайте то, что в неё не вошло —
  новые изменения идут в заметки следующей.
- Скриншоты для README лежат в `docs/screenshots/`; если изменение меняет то,
  что на них видно, снимок нужно переснять.

## Работа с телевизорами владельца

Тестовые устройства — личные телевизоры и приставки владельца, на них смотрят.

- Устройство свободно, только если владелец сейчас сказал об этом или на экране
  домашний экран лаунчера. Если впереди `com.dreamcast.app` или любое другое
  приложение — устройство занято: остановитесь и спросите. Проверка занятости
  должна прерывать команду, а не только печатать результат.
- Не будите устройство из заставки сами.
- Не трогайте установленный `com.dreamcast.app`: не переустанавливайте, не
  удаляйте, не чистите данные. Для опытов — отдельные пакеты
  (`-PnativeDebugSuffix`), после проверки удаляйте их.
- Нажатия клавиш отправляйте только когда впереди ваш тестовый пакет.
  Никогда не нажимайте Home и системные клавиши и не запускайте
  автоматизацию, которая это делает (UiAutomator `pressHome()` открывал выбор
  профиля Google TV), без объяснения и согласия владельца.
- Журналы читайте только узко: теги `DCTV_*` (`DCTV_NATIVE_PLAYER`,
  `DCTV_DECODER` и т. п.). Не выгружайте полный logcat, список приложений,
  данные аккаунтов и профилей — это личные данные владельца.
- Baseline Profile снимается только внутри приложения (сценарий в
  `baselineprofile/`): включает плеер и dav1d, просмотр dav1d — 10–15 секунд,
  настройки качества сбрасываются перед каждым проходом. Перед запуском
  объясните фазы (сборка идёт долго, на экране ничего не происходит) и
  сообщайте о ходе. Результат пишется только в конце — не предлагайте
  прерывать на середине.
- Во время долгих проверок пишите короткие комментарии о том, что делаете.

## Как общаться с владельцем

- Вопрос — это вопрос, а не задание: ответьте и дождитесь явного «делай»,
  прежде чем менять код.
- Отчитывайтесь честно: что проверено, на каком устройстве, что нет.

## Устройство плеера (кратко)

- `PlayerActivity` — экран плеера. Меню — `PlayerMenus`/`PlayerTrackMenu`,
  перемотка с превью — `SeekPreview`, таймеры — `PlayerTimers`, восстановление
  после ошибок — `PlayerRecovery`, сохранённое состояние — `PlayerSavedState`.
- Декодер: режимы «Авто», «Аппаратное», «Программное AV1 — dav1d»
  (`VideoDecoding.kt`, `chooseVideo`). Смена декодера в меню пересоздаёт
  экран (`recreate()`) с той же серии и позиции; повторный выбор того же
  пункта ничего не делает (`unchangedChoice`).
- Аппаратное видео выводится через `TextureView`
  (`res/layout/hardware_player.xml`), dav1d — через свой GL-вывод
  (`dav1d_player.xml`).
- Качество «Авто» для dav1d подбирается под устройство:
  `SoftwareFrameMonitor` (окна по 5 с) и `SoftwareAutoQuality` (предел
  разрешения по устройству, проба вверх только на пределе, паузы 5/20/50
  серий). Подробности — в README, раздел «Декодирование видео».
- Поток по умолчанию — HLS (`UiSnapshot.DEFAULT_STREAM_TECHNOLOGY`);
  сохранённый пользователем выбор не перезаписывается.

## Открытая проблема: телевизор Candy (Google TV, MediaTek)

Устройства нет у владельца, владелец телевизора отвечает редко — разбирайтесь
по коду и журналам, не рассчитывая на вопросы к нему.

- Симптомы: аппаратный AV1 желтит (dav1d, YouTube и mpv — нет); переход
  dav1d → «Аппаратное» в работающем плеере вешал весь телевизор до
  отключения питания.
- Не помогло (0.9.9): не передавать декодеру цветовые параметры
  (`BitstreamColorVideoRenderer` оставляет их потоку) и пауза 1 с между
  декодерами.
- В 1.0.0: вывод через `TextureView` вместо видеослоя и пересоздание экрана
  при смене декодера. Ждём отзыва владельца.
- Если не поможет — следующий вариант libmpv (GPL-3.0-or-later, около
  +20–25 МБ к APK). Оценка лежит в локальной ветке `mpv_test`
  (`docs/MPV_EVALUATION_RU.md`), на GitHub её нет.
