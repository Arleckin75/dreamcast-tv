<h1 align="center">Dream Cast TV</h1>

<p align="center">Неофициальная модификация открытого Android-клиента Dream Cast для Android TV и Google TV.</p>

> **Версия проекта: v0.7.1.** Разработка и тестирование двух вариантов Android TV завершены; публикация подписанного релиза проходит отдельную проверку. Актуальные файлы для установки см. на [GitHub Releases](https://github.com/Arleckin75/dreamcast-tv/releases). Проект не является официальным приложением Dream Cast и не связан с администрацией сервиса.

## Возможности

- Каталог аниме с постерами и описаниями, карточками релизов и списками эпизодов.
- Поиск с обновлением результатов при вводе.
- Библиотека, календарь релизов и уведомления.
- Полноэкранное воспроизведение с паузой, перемоткой и управлением с пульта.
- **Два независимых варианта приложения:** `software_AV1` с LibVLC и `hardware_AV1` с Media3 / ExoPlayer. Автоматического переключения между движками нет.
- **Выбор качества до запуска эпизода:** Auto / 480p / 720p / 1080p. Выбранное качество сохраняется.
- Локальный профиль `TV`, закладки, сохранение позиции эпизода и раздел «Продолжить просмотр».
- Интерфейс для телевизора с верхней навигацией, тёмной темой по умолчанию и запуском без мастера первоначальной настройки.

Доступность видео зависит от источника, сети и прав на соответствующий контент.

## Какую версию APK выбрать

| Вариант | Видеодвижок | Для каких устройств |
| --- | --- | --- |
| **software_AV1** | LibVLC, программное декодирование AV1 | **old ATV** и другие Android TV-устройства без аппаратного декодирования AV1 |
| **hardware_AV1** | Media3 / ExoPlayer | Android TV / Google TV с аппаратной поддержкой AV1 |

Оба варианта используют один идентификатор приложения — `com.dreamcast.app`. **Одновременно установить их нельзя:** выберите один APK под своё устройство. Если аппаратная поддержка AV1 неизвестна, проверьте характеристики устройства перед установкой.

Для `software_AV1` на **old ATV** практичный выбор — **720p**, поскольку программное декодирование AV1 в 1080p может перегружать процессор. В режиме Auto для программного варианта используется 720p; аппаратный вариант использует адаптивный HLS.

## Что нового в v0.7.1

- Полностью разделены зависимости видеодвижков: в `software_AV1` нет ExoPlayer, в `hardware_AV1` нет LibVLC. Это проверяется автоматическим аудитом APK.
- Добавлены четыре режима качества: **Auto, 480p, 720p и 1080p**; выбор выполняется до воспроизведения.
- Для `software_AV1` исправлен сбой при выходе из плеера кнопкой Back на **old ATV**; изменён порядок остановки и освобождения ресурсов LibVLC.
- Исправлено сохранение и восстановление позиции просмотра после выхода из LibVLC.
- Для Android TV-сборок оставлены ARM-архитектуры `armeabi-v7a` и `arm64-v8a`; исключены нативные библиотеки x86/x86_64.
- Добавлен автоматический контроль состава APK, архитектур и — для Release — подписи, версии и контрольных сумм SHA-256.

**Проверено на устройствах:** воспроизведение, выход Back, сохранение и продолжение просмотра для `software_AV1` на **old ATV**; выбор всех четырёх режимов качества проверен для обоих вариантов. Успешная Debug-проверка не заменяет проверку обновления подписанного Release APK.

## Управление пультом

| Кнопка | Действие |
| --- | --- |
| Стрелки D-pad | Навигация; в плеере влево/вправо — перемотка |
| OK / Select | Выбор элемента; в плеере — воспроизведение/пауза |
| Back (коротко) | Возврат на предыдущий экран; из плеера — к эпизодам; при открытой клавиатуре — сначала закрытие клавиатуры |
| Back (удержание около 1,5 с) | Выход из приложения, если устройство передаёт удержание приложению |

В поиске после закрытия клавиатуры стрелка вниз переводит фокус к результатам. При возврате из карточки сохраняется введённый запрос.

## Установка

Скачайте подходящий **подписанный Release APK** на странице [Releases](https://github.com/Arleckin75/dreamcast-tv/releases), когда v0.7.1 появится в списке опубликованных релизов:

- `DreamCast-TV-v0.7.1-software_AV1-release.apk` — для **old ATV** / программного AV1.
- `DreamCast-TV-v0.7.1-hardware_AV1-release.apk` — для аппаратного AV1.

Установите APK вручную на Android TV / Google TV. Для обновления **поверх v0.7.0 без удаления данных** необходимы одинаковый идентификатор приложения, совместимый сертификат подписи и более высокий `versionCode`. Не удаляйте установленную версию ради обновления, пока совместимость подписей не подтверждена.

Debug APK и Release APK могут быть подписаны разными ключами; установка одного поверх другого с тем же package ID может быть запрещена Android. Для проверки файла доступны сопутствующие `.sha256` после публикации релиза.

## Сборка и GitHub Actions

Требуются Flutter SDK, Android SDK и совместимый JDK. В проекте предусмотрены две Android product flavors:

| Workflow | Назначение |
| --- | --- |
| **Build Dream Cast TV APK** (`.github/workflows/build-tv-apk.yml`) | Debug-сборки и аудит обоих видеодвижков; без доступа к ключам Release |
| **Build Dream Cast TV Release APK** (`.github/workflows/build-tv-release.yml`) | Подписанные Release APK, проверка сертификатов и публикация после успешного аудита |

Для локальной сборки используйте Flutter/Gradle-конфигурацию проекта. Вариант `software_AV1` требует подготовки Android-плагина через `scripts/prepare_software_av1.py`.

## Основные технологии

Flutter / Dart, Riverpod, GoRouter, Dio, Drift, LibVLC (`software_AV1`) и AndroidX Media3 / ExoPlayer (`hardware_AV1`). Данные каталога извлекаются сетевым слоем и парсером приложения, без встроенного WebView.

## Изменения в develop после v0.7.1

Этот раздел описывает изменения исходников в `develop`. Основной текст выше взят из локальной ветки `main` без изменений; сведения ниже уточняют поведение и порядок сборки в `develop`. Перенос изменений в `main` выполняется владельцем проекта отдельно.

### Онлайн-просмотр и выбор видеодвижка

- Android product flavor стал единственным источником выбора плеера в Dart через `appFlavor`. Отдельный параметр `AV1_PLAYER` больше не требуется.
- `softwareAv1` предназначен для онлайн-просмотра: скрыты кнопки скачивания и вкладка офлайн-серий, добавлен запрет загрузок на уровне сервиса. Существующие локальные копии не выбираются для воспроизведения в этом варианте.
- Ограничение LibVLC-плеера сетевыми HTTP/HTTPS-адресами сохранено; поддержка локальных файлов в software-плеер не добавлялась.
- В `hardwareAv1` сохранено офлайн-воспроизведение. Перед открытием локального плейлиста проверяется наличие файла; если он отсутствует, приложение переходит к получению сетевого потока. Проверка действует и при переходе к следующей серии.
- В Android-манифесте отключено глобальное разрешение незашифрованного HTTP-трафика. Для сетевых источников следует использовать HTTPS.

### Загрузки и фоновая работа

- Добавлена сохраняемая в SQLite очередь отдельных эпизодов, включая пакетные загрузки. Запись эпизода и его задания выполняется атомарно в одной транзакции.
- Новая загрузка добавляется в очередь вместо остановки уже работающего foreground-сервиса.
- Постановка заданий и остановка пустой очереди согласованы через блокировку записи SQLite. У заданий есть идентификаторы, предотвращающие удаление нового задания завершающимся предыдущим запуском той же серии.
- Отмена передаётся через состояние в базе данных: фоновый обработчик обнаруживает её и отменяет собственный `CancelToken`, даже если интерфейс и загрузчик работают в разных изолятах.
- Добавлена возможность отменить эпизод, ожидающий в очереди. Во время отмены интерфейс показывает соответствующее состояние.
- После ошибки или отмены удаляются частично скачанные ресурсы. Путь к локальному плейлисту сохраняется ещё до завершения загрузки, чтобы его можно было использовать для очистки.
- Ошибка загрузки возвращает отрицательный результат фоновой задаче, а не маскируется как успешное выполнение. В пакетной загрузке отмена одной серии не отбрасывает остальные.
- Незавершённая очередь восстанавливается при запуске приложения. При остановке сервиса текущие запросы отменяются, а незавершённое задание сохраняется для продолжения; завершение обработчика ожидает закрытия подключения к базе.
- Для базы включены WAL и ожидание занятой SQLite-блокировки, необходимые для одновременной работы интерфейса и фонового подключения.
- Исправлена сериализация списка идентификаторов серий в данных пакетных заданий.
- HLS с отдельной аудиодорожкой или диапазонами байтов пока не поддерживается загрузчиком: такие плейлисты отклоняются вместо сохранения повреждённой офлайн-копии. Это ограничение относится к скачиванию, а не к онлайн-воспроизведению.

### Продолжение просмотра и маршруты

- «Продолжить просмотр» открывает маршрут с идентификаторами релиза и эпизода. Для сетевого просмотра повторно извлекаются данные серии и поток, вместо безусловного открытия старого сохранённого URL.
- Сохранённая потоковая сессия с истёкшим `expiresAt` больше не возвращается как пригодная для воспроизведения.
- Срок действия потока проверяется независимо от срока хранения кэша, включая настройку «Не удалять автоматически».
- Подключено восстановление релиза по ID из переданного объекта, локального кэша или страницы источника.
- Добавлены маршруты `/release/:id/episodes` и `/watch/:releaseId/:episodeId`; `/release/:id` также может открываться без объекта в `GoRouter.extra`.
- Старые входы `/episodes` и `/watch` перенаправляются на маршруты с идентификаторами. Добавлены состояния загрузки, ошибки и повторной попытки при восстановлении экранов.

### Локальные данные и уведомления

- Добавлено защищённое чтение JSON-записей библиотеки, подписок, истории уведомлений и сетевого кэша. Повреждённая запись или неверный тип данных не должны ломать чтение остальных записей.
- Для фоновой проверки подписок добавлена ротация с сохранением позиции. За один запуск обрабатывается до 40 подписок, а следующие запуски переходят к остальным; сортировка по ID сохраняет порядок независимо от обновления метаданных релизов.

### Зависимости, Android и сборочные инструменты

- Закреплена версия Flutter **3.41.5**, используемая с Dart **3.11.3**; добавлен файл `.flutter-version`. Для Android-сборок используется **JDK 17**.
- Версия в `pubspec.yaml` приведена к **`0.7.1+710001`**. Локальные сборки и CI берут `versionName` и `versionCode` из одного источника; отдельные переопределения номера сборки удалены из основного workflow.
- Добавлены зависимости `integration_test` и `path_provider_platform_interface` для тестирования, обновлён `pubspec.lock`.
- `prepare_software_av1.py` теперь создаёт локальный `pubspec_overrides.yaml`, а не редактирует основной `pubspec.yaml`. Параметр `--hardware` убирает только override, созданный этим скриптом; чужой файл overrides не перезаписывается.
- Добавлен `scripts/build_tv.dart`: он проверяет версию Flutter, выбирает видеоплагин и flavor, собирает ARM APK и восстанавливает исходные overrides и lock-файл, а также граф зависимостей. Параметр `--check` дополнительно запускает анализатор и тесты.
- Gradle проверяет соответствие видеоплагина явно запрошенному flavor и требует отдельной сборки каждого варианта. Проверка учитывает, что граф задач Flutter может содержать вспомогательные задачи другого flavor.
- Удалено резервное назначение debug-ключа для Release при отсутствии release-конфигурации подписи.
- Добавлены файлы Gradle Wrapper: `android/gradlew`, `android/gradlew.bat` и `android/gradle/wrapper/gradle-wrapper.jar`.

Примеры команд для разработчика при установленном Flutter 3.41.5 и настроенном JDK 17:

```sh
flutter pub get
dart run scripts/build_tv.dart software debug --check
dart run scripts/build_tv.dart hardware debug --check
```

Для Release замените `debug` на `release` и предварительно настройте `android/key.properties`. Команды приведены как инструкция; сборку APK следует запускать отдельно, когда она нужна.

- Добавлен `verify.yml`, запускающий проверки при push и pull request в `develop`: анализатор, общий набор тестов, отдельные тесты software-flavor и проверку синтаксиса Python-инструментов.

- Анализатор теперь проверяет `integration_test/` и `test_driver/`; локальная папка инструментов `.tools/` исключена из анализа.

## Адаптация develop только для Android TV / Google TV

В этой доработке интерфейс и конфигурация ориентированы на управление телевизионным пультом. Описание предыдущих изменений выше сохранено как история разработки.

- Leanback объявлен обязательным; убрана обычная категория телефонного launcher. Название приложения приведено к `Dream Cast TV`, баннер `320×180` размещён в `drawable-xhdpi`.
- Основная Activity и Flutter-интерфейс используют landscape. При запуске и выходе из плеера сохраняется полноэкранный TV-режим; портретная ориентация больше не включается.
- Телефонная нижняя навигация удалена. На всех размерах окна используется постоянное верхнее меню «Главная / Библиотека / Календарь / Настройки» с начальным фокусом и доступом к контенту через D-pad.
- Для обновления каталога, календаря, уведомлений и сведений о кэше добавлена явная кнопка «Обновить». Жест pull-to-refresh больше не требуется и не используется.
- Нижние выдвижные панели заменены центрированными TV-диалогами с ограничением размеров, начальным фокусом и замкнутым порядком обхода. Настройки фокусируют выбранное значение; список серий фокусирует первый доступный эпизод.
- Экранные кнопки навигации «Назад» убраны. Обычный Back закрывает клавиатуру или диалог, возвращает с вложенного экрана, а на главной выходит в системный TV-launcher. Удержание Back остаётся дополнительным поддерживаемым способом выхода.
- В hardware-плеере удалены сенсорные жесты. Вверх/вниз показывают панель с фокусом на воспроизведении, OK управляет выбранной кнопкой, влево/вправо при скрытой панели перематывают на 10 секунд. Скрытые элементы исключены из фокуса и семантики.
- Автоскрытие плеера возвращает фокус на поверхность видео, но не забирает его у открытого диалога качества. После закрытия диалога фокус возвращается на управление воспроизведением.
- В software-плеер добавлена обработка отдельных медиа-кнопок Play и Pause. PiP сохранён для устройств TV, которые его поддерживают.
- Увеличены подписи карточек и базовая типографика, усилена подсветка фокуса, добавлена рамка выбранной пультом карточки. Вместо технических сообщений на постерах отображается «Нет постера».
- Внешние ссылки показываются в TV-диалоге для открытия на другом устройстве; приложение больше не пытается запускать браузер или социальное приложение на телевизоре. Текст лицензии прокручивается стрелками пульта.
- Удалены неиспользуемые зависимости `cupertino_icons` и `url_launcher` с его платформенными реализациями. Мобильные заголовки сетевого клиента сохранены для совместимости с источником: они не определяют тип интерфейса приложения.
- Добавлены widget-тесты с настоящими событиями клавиш D-pad/OK для меню, диалогов, обновления, прокрутки, клавиатуры, Back и плеера. Тесты плеера используют подменённый видеодвижок и не запускают реальное сетевое видео.

Для этой доработки APK не собираются. Проверка на физическом Android TV / Google TV, включая особенности конкретного пульта, остаётся отдельным этапом.

## Доработки develop по плану 0.7.2 → 0.7.6 → 0.7.3

Это изменения исходников для следующих этапов плана. Номер приложения пока остаётся `0.7.1+710001`; готовность новых релизов на физических телевизорах не заявляется.

### 0.7.2 — кэширование и лишние запросы

- Каталог, поиск и расписание используют свежий кэш до сетевого запроса. Актуальность каталога и поиска ограничена 20 минутами, расписания — 30 минутами независимо от выбранного срока хранения, включая «не удалять автоматически».
- Кнопка «Обновить» каталога и расписания принудительно обращается к серверу. При сетевой ошибке сохранённые данные доступны с отметкой устаревания; отменённые запросы не подменяются данными из кэша.
- Отменённый старый поиск и старая загрузка следующей страницы больше не перезаписывают результат более нового запроса или обновления каталога.
- Повреждённые записи кэша каталога и расписания не блокируют попытку загрузки из сети. Кэш потоков также учитывает свой двухчасовой срок актуальности.
- Размер декодирования постеров ограничен шириной отображения с учётом плотности экрана и пределом 1920 пикселей. Это ограничивает расход памяти на большие исходные изображения; замеры скорости на реальном TV ещё нужны.

### 0.7.6 — прогресс и продолжение просмотра

- Позиция и запись «Продолжить просмотр» сохраняются одной транзакцией SQLite. Отрицательные позиции и позиции за пределами длительности нормализуются.
- Hardware-плеер сохраняет прогресс при паузе, уходе приложения в фон, закрытии экрана и ошибке. Записи выполняются последовательно; начальная нулевая позиция до восстановления просмотра не затирает сохранённую.
- Завершённый эпизод открывается с начала. После завершения последнего открытого эпизода прежняя недосмотренная серия этого же релиза не возвращается в «Продолжить просмотр».
- В LibVLC сравнивается время сохранения нативной и общей позиции вместо выбора максимального значения. Это сохраняет возможность продолжить просмотр после перемотки назад. До восстановления позиции и после ошибки нулевое значение плеера не записывается поверх прогресса; при завершении учитывается отдельный признак completed.

### 0.7.3 — запуск и восстановление плеера

- Исключены одновременные запуски инициализации. После асинхронных операций проверяется, что экран ещё открыт и контроллер актуален; таймеры старого плеера отменяются.
- Действие «Повторить» для сетевого видео заново получает страницу релиза, эпизоды и ссылки на потоки, сохраняет тип/качество при наличии соответствующего варианта и восстанавливает позицию.
- Ошибка LibVLC передаётся в Flutter отдельным признаком, чтобы после возврата из нативного плеера можно было повторить запуск. Плееры остаются независимыми, переключения движка во время работы нет.

Добавлены проверки кэша, отмены и гонок поиска, транзакционного сохранения, завершения эпизода, жизненного цикла и повторного открытия с обновлённой ссылкой. Тесты используют SQLite в памяти и подменённый видеодвижок. APK для этих изменений не собирались; Kotlin-изменения LibVLC требуют отдельной проверки сборкой и на устройстве.

Проверки этих доработок: общий набор — **53 теста пройдены**, 2 software-теста пройдены отдельно с `--flavor softwareAv1`; `flutter analyze --no-pub` и `git diff --check` — без замечаний.

## Подготовка NDK в GitHub Actions

При debug-сборке software_AV1 установка NDK `28.2.13676358` завершилась ошибкой `Archive is not a ZIP archive`. Ошибка возникла при распаковке скачанного компонента Android SDK, до компиляции приложения.

- Версия NDK закреплена в `.android-ndk-version`; Gradle и скрипт подготовки используют один файл.
- В debug- и release-workflow перед сборкой добавлена явная установка NDK через SDK Manager. Проверяются версия, `ndk-build` и Linux-компилятор clang.
- Незавершённая установка выбранной версии NDK и временные файлы SDK очищаются перед повторной попыткой. Предусмотрены три попытки с ограничением времени каждой; уже установленный исправный NDK используется повторно.
- Скрипт проверен с подменённым SDK Manager: сбой первой попытки, очистка, успешный повтор, повторное использование и остановка после трёх ошибок. Проверка включена в workflow verify. Bash-синтаксис, actionlint и git diff --check — без замечаний.

Локальная загрузка NDK и сборка APK не запускались. Исправление подготовки окружения требует подтверждения следующим запуском GitHub Actions после отправки изменений в `develop`.
