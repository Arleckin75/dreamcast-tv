# Dream Cast TV — Kotlin

Неофициальный клиент Dream Cast для **Android TV и Google TV**: каталог аниме,
библиотека и просмотр серий с управлением пультом.

Ветка `Kotlin` содержит нативную Android-версию **0.8.6-kotlin** на Kotlin и
Jetpack Compose / TV Material. Приложение и его сборка работают без Flutter.
Минимальная версия Android — **6.0 (API 23)**.

## Чем отличается от main

В `main` находится Flutter-версия 0.8.5. В `Kotlin` заново реализованы интерфейс,
навигация, работа с данными и аппаратный плеер; программный плеер использует
адаптированную реализацию LibVLC из исходного Android-модуля.

| Область | `main` | `Kotlin` |
| --- | --- | --- |
| Приложение | Flutter / Dart, проект в корне | Kotlin / Compose, проект `native-android/` |
| Главная | Интерфейс Flutter | Баннер последних обновлений и ряд «Продолжить просмотр» |
| Оформление | Темы и акцентный цвет | Темы, акцент, плавный градиент по цветам выбранной обложки |
| Выбор серий | Экран исходной версии | Всплывающее окно поверх текущего экрана |
| Плееры | Отдельные software/hardware-варианты | LibVLC или Media3 с общей панелью управления и настройками справа |
| Данные | Drift / SharedPreferences | SQLite с чтением прежней схемы и настроек |
| Сборка | Flutter SDK и Android SDK | JDK 17, Android SDK и Gradle Wrapper |
| Тестовые APK в Actions | `software_AV1-debug`, `hardware_AV1-debug` | `kotlin-software-debug`, `kotlin-hardware-debug` |

Исходники Flutter сохранены для сравнения и проверки переноса данных.
Подробный статус функций и проверок — в [документе о переносе](docs/KOTLIN_MIGRATION.md).

## Возможности

- Каталог с пагинацией, фильтрами по году и нескольким жанрам; поиск и история запросов.
- Карточки тайтлов с описанием, метаданными, списком серий и отметками просмотра.
- Библиотека со статусами «Смотрю», «Просмотрено», «Брошено» и «В планах».
- Расписание, подписки на новые серии и история уведомлений.
- Сохранение позиции и продолжение просмотра, в том числе после перезапуска приложения.
- Выбор доступного потока и качества, пауза, перемотка ±10 секунд и следующая серия.
- Автопереход к следующей серии с отсчётом 5 секунд и возможностью отмены.
- Локальный профиль, системная / светлая / тёмная тема, акцент и системные цвета.
- Настраиваемый срок хранения кэша, статистика и ручная очистка.

## Интерфейс для телевизора

Верхняя навигация доступна во всех основных разделах. На главной последние
обновления представлены баннером: при фокусе на «Подробнее» стрелки влево/вправо
переключают тайтлы. Ниже расположен ряд продолжения просмотра с прогрессом серий.

Фокус выделяется рамкой и плавным увеличением постера. Общий фон подстраивается
под цвета выбранной обложки на главной, включая баннер, в каталоге, результатах
поиска, библиотеке и карточке тайтла. Цвета меняются плавно; при недоступной
обложке используется фон выбранной темы.

Кнопка «Серии» открывает список в диалоге. В фильтре жанров можно выбрать
несколько пунктов; «Применить» и «Сбросить» находятся на панели справа.

## Какую версию выбрать

| Вариант | Движок | Для каких устройств |
| --- | --- | --- |
| **hardware AV1** | Media3 / ExoPlayer | Android TV и Google TV с аппаратным декодированием AV1 |
| **software AV1** | Сокращённый LibVLC, программное декодирование | Устройства без аппаратной поддержки AV1, включая Cosmos / old ATV |

Для Cosmos рекомендуется **720p**. Software-сборка содержит библиотеки ARMv7 и
ARM64. Возможность воспроизведения конкретного качества зависит от устройства
и доступных потоков.

У плееров общая панель: название, серия, шкала прогресса, кнопки воспроизведения,
перемотки и перехода к следующей серии. Панель автоматически скрывается.
В hardware-варианте справа доступны качество, скорость и поток; автоматическая
«Картинка в картинке» при уходе из плеера сохранена на поддерживаемых устройствах.
В software-варианте доступен выбор качества. Отдельные текстовые субтитры в нём
отключены; надписи, уже встроенные в изображение видео, отображаются.

## Оптимизация

Сетевые запросы, разбор HTML/JSON и операции с хранилищем выполняются в фоне.
Совпадающие загрузки объединяются; отменённые запросы не обновляют закрытый экран.
Меню использует подготовленные снимки данных, ленты и палитры обложек кэшируются.

Дисковый кэш автоматически обслуживается с целевым ограничением 512 записей /
16 МиБ данных. При сетевом сбое приложение может показать сохранённые данные.
Очистка кэша сохраняет библиотеку и историю просмотра.

Устранена долгая инициализация базы шрифтов LibVLC при первом запуске software-плеера.
На Cosmos локальный тест AV1 720p показал **3,4 секунды вместо 59 секунд** до
начала воспроизведения. Это замер локального источника; загрузка серии из
интернета дополнительно зависит от сети и сервера.

Подробности: [оптимизация Kotlin](docs/KOTLIN_OPTIMIZATION_RESULTS_RU.md) и
[первый запуск на Cosmos](docs/COSMOS_SOFTWARE_STARTUP_RU.md).

## Скачать и установить

Тестовые Kotlin-сборки доступны в
[GitHub Actions → Verify native Kotlin TV](https://github.com/Arleckin75/dreamcast-tv/actions/workflows/build-native.yml).

1. Выберите успешный запуск для ветки **`Kotlin`**.
2. Скачайте артефакт **`kotlin-hardware-debug`** или **`kotlin-software-debug`**.
3. Распакуйте архив и установите APK на телевизор.

Ручной запуск workflow `Build Dream Cast TV APK` для ветки `Kotlin` также
собирает нативные debug APK. Опубликованные выпуски находятся в
[Releases](https://github.com/Arleckin75/dreamcast-tv/releases); принадлежность
конкретного APK к Kotlin-версии проверяйте по описанию выпуска.

Debug-сборка имеет applicationId `com.dreamcast.app.kotlin` и устанавливается
рядом с основной версией `com.dreamcast.app`. У них раздельные данные.
Оба debug-варианта Kotlin используют один applicationId, поэтому для одновременной
установки hardware и software нужны сборки с разными суффиксами.

Release использует прежний applicationId `com.dreamcast.app`. Обновление поверх
Flutter-версии требует подписи тем же ключом. Реализовано чтение прежней базы,
профиля, библиотеки, подписок, истории, позиций и настроек; полная проверка
подписанного обновления на телевизоре ещё не завершена.
Удаление приложения удаляет его локальные данные.

## Управление пультом

- **Стрелки** — навигация; в плеере — управление панелью и перемоткой.
- **OK** — выбор и активация выделенной кнопки.
- **Back** — закрытие диалога или возврат; в плеере сначала скрывает панель,
  затем закрывает плеер. В окне автоперехода отменяет переход.

## Сборка из исходников

Требуются **JDK 17**, **Android SDK Platform 36**, Build Tools 36.0.0 и настроенные
`JAVA_HOME` / `ANDROID_HOME`. Команды выполняются из корня репозитория.

Windows PowerShell:

```powershell
./scripts/build_native.ps1 -Player hardware
./scripts/build_native.ps1 -Player software
./scripts/build_native.ps1 -Player hardware -Test
./scripts/build_native.ps1 -Player software -Test
```

Для software сначала подготовьте проверенный Maven-артефакт `libvlc-tv-maven`
в `.tools/libvlc-tv/maven` по [инструкции LibVLC](third_party/libvlc_tv/README.md).
Hardware собирается независимо от LibVLC.

Linux / macOS:

```sh
bash android/gradlew -p native-android :app:assembleHardwareAv1Debug
bash android/gradlew -p native-android :app:assembleSoftwareAv1Debug
```

APK находятся в
`native-android/app/build/outputs/apk/{hardwareAv1,softwareAv1}/debug/`.
Для release передайте скрипту `-Configuration release`; подпись настраивается
через `android/key.properties`. Без ключа получается unsigned APK.

Архитектура, команды проверок и настройка тестового окружения описаны в
[native-android/README.md](native-android/README.md).

## Статус проверок

Нативная версия находится в разработке. Оба варианта собираются; аудит APK
проверяет отсутствие Flutter runtime и разделение Media3 / LibVLC.
Unit-тесты покрывают парсеры, кэш, запросы, библиотеку, историю, прогресс и
совместимость с прежней схемой базы данных.

На Cosmos проверены каталог и управление пультом, программное воспроизведение
AV1 720p, сохранение позиции, следующая серия, первый запуск и восстановление
видеовывода после сворачивания. На Google TV Streamer проверены аппаратный
AV1, HLS/DASH, качество, скорость и вход в PiP.

Остаются проверки возврата из PiP, фоновых уведомлений в Doze, подписанного
обновления с реальными данными и полной матрицы воспроизведения на устройствах.
Перечень подтверждённых сценариев и ограничений — в
[статусе переноса](docs/KOTLIN_MIGRATION.md).
