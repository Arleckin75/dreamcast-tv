# 0.7.2 — скорость и кэширование

## Изменения

Подготовка уведомлений и WorkManager перенесена за первый кадр интерфейса. До этого bootstrap ожидал инициализацию WorkManager до `runApp`. Фоновый запуск сохраняет существующую обработку ошибок и последовательность: сервис уведомлений, затем синхронизация расписания. `syncFromPreferences` самостоятельно инициализирует WorkManager. Величина ускорения пока не измерена.

Каталог уже возвращает свежий кэш без HTTP (TTL 20 минут); принудительное обновление обращается к сети, при ошибке допускается помеченный устаревший кэш, отменённые запросы не превращаются в успешные ответы из кэша. Эти сценарии покрыты `release_cache_test.dart`. TTL потоков, обновление подписанных ссылок, Auto и профиль LibVLC не менялись.

## Метрики

В debug-сборках автоматически включены короткие JSON-записи `DCTV_PERF`. В Dart их можно отключить через `--dart-define=DREAM_CAST_PERFORMANCE=false`; для включения в profile использовать `true`. Нативная запись LibVLC сейчас включена только у debuggable-приложения. В метриках нет URL, запросов поиска или токенов.

| Событие | Измеряемый интервал |
|---|---|
| `startup.bootstrap` | Подготовка Flutter binding, настроек и объекта БД; открытие SQLite может произойти позже при первом запросе |
| `startup.first_framework_frame` | От входа в Dart main до post-frame callback первого Flutter-кадра |
| `home.catalogue_framework_frame` | От создания состояния главного экрана до кадра с результатом каталога, включая пустой результат; загрузка всех постеров не включена |
| `catalogue.load` | Чтение/разбор кэша и при необходимости HTTP, разбор ответа и запись кэша; источник `cache`, `network`, `stale_cache`; ошибка/отмена помечаются отдельно |
| `player.hardware.initialize` | Вызов `VideoPlayerController.initialize` до завершения или ошибки |
| `player.software.output_created` | От создания native Activity до первого положительного Vout LibVLC, включая разрешение плейлиста |

Первый Flutter-кадр не означает готовый каталог или физический показ кадра дисплеем. Готовность hardware-контроллера и создание software-видеовывода не доказывают показ первого декодированного кадра; напрямую сравнивать их как «кто быстрее показывает видео» нельзя. Поиск потоков до открытия плеера не включён в эти два интервала. Для оценки от нажатия Play до изображения нужна отдельная сквозная метрика первого отображённого видеокадра.

## Проверка на телевизоре

1. Установить новую debug-сборку из GitHub Actions. На старой установленной сборке этих метрик нет. APK локально не собирается и автоматически не устанавливается.
2. На одном устройстве и одной сборке выполнить не менее пяти запусков из остановленного состояния и отдельно пяти возвратов в уже работающий процесс. Способ остановки согласуется отдельно: сборщик сам не завершает приложение и не очищает данные.
3. Разделить каталог из свежего кэша, загрузку при отсутствии/истечении кэша и резервный ответ при ошибке сети. Не очищать настройки, историю и закладки ради замера. Не смешивать поисковые страницы с главной и разные размеры страниц; исходный порядок записей и PID сохраняются в CSV.
4. Проверить запуск одинакового эпизода с одинаковой позиции и качеством отдельно в обоих плеерах. Для old ATV использовать 720p; дальнейшее исследование 1080p исключено пользователем.
5. После каждого набора прочитать журнал, сохранив новый каталог:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/read_tv_performance.ps1 -Serial 192.168.0.9:5555 -OutputDirectory .tools/tv-performance-run1
```

Скрипт только читает последние 10 000 строк logcat: не нажимает кнопки, не запускает и не останавливает приложение, не очищает журнал. `records.csv` содержит исходные строки с временем и PID, `summary.csv` — медиану, P90 методом ближайшего ранга, минимум/максимум и количество измерений по событию/источнику/результату. История журнала может содержать другие процессы, поисковые страницы и предыдущие сборки; перед сравнением отобрать один сценарий по исходным записям. Повторные чтения пересекаются, их нельзя складывать как независимые замеры. При малом числе запусков P90 не является надёжной оценкой.

Для сравнения debug и profile держать отдельные таблицы; показатели debug не выдавать за производительность release. Скорость сети и серверов записывать как условия опыта. Размер памяти измерять существующим `collect_tv_stability.ps1` отдельно от времени загрузки.

## Статус

Инструменты и изменение порядка запуска подготовлены в develop. Реальные времена на TV до/после ещё не собраны; этап 0.7.2 не объявляется завершённым только по наличию журналирования. Проверка software-720p по памяти за 10 минут описана отдельно в `TV_STABILITY_2026-11-02.md` и не является замером скорости запуска.

Локальные проверки: все 61 Flutter-тест прошли, `flutter analyze --no-pub` без замечаний. Kotlin-исходники old ATV отдельно скомпилированы против Android 36 и LibVLC без создания APK. Скрипт сбора проверен на синтетических Flutter/native-строках: обе формы маркера распознаются, медиана и P90 рассчитаны корректно. Эти проверки не подменяют измерение скорости на TV.
