# LibVLC 3.7.7: размер и профиль сокращённой сборки

Исследование для `develop`. Рабочая зависимость остаётся `org.videolan.android:libvlc-all:3.7.7`. APK и новая библиотека не собирались. Измерения ниже относятся к AAR из локального Gradle-кэша, а не к APK из GitHub Actions.

## Измеренный состав

AAR: **92 576 688 байт**, SHA-256 `b48dab96e0e90e34cce3861963500c144a5aadb1b249d501d6a4b104d849e61b`.

| Файл | ARMv7, байт | ARM64, байт |
|---|---:|---:|
| `libvlc.so` | 39 822 028 | 45 875 392 |
| `libvlcjni.so` | 67 112 | 97 736 |
| `libc++_shared.so` | 554 808 | 9 290 184 |

Размеры — до ZIP-сжатия. AAR содержит также x86 и x86_64; проект уже исключает их из APK. Повторно считать их исключение новой экономией нельзя.

`classes.jar`: 154 730 байт. Все 42 файла `assets/lua` и `assets/hrtfs` вместе: 220 723 байта, в архиве 101 322 байта. Только удалением assets заметно сократить APK не получится.

## ELF и stripping

- В ARM `libvlc.so` и `libvlcjni.so` нет `.debug_*`, `.symtab` и `.strtab`. Основной код VLC уже очищен от этой информации.
- В ARM64 `libc++_shared.so` есть 7 443 034 байта `.debug_*` и 472 193 байта статических таблиц символов/строк.
- `llvm-strip --strip-unneeded` на отдельной копии C++ runtime уменьшил файл с **9 290 184 до 1 374 336 байт**. Разница: 7 915 848 байт несжатого файла. `DT_NEEDED` и `SONAME` не изменились. Это проверка структуры, а не тест воспроизведения.
- [Android Gradle Plugin удаляет отладочную информацию при упаковке](https://developer.android.com/build/include-native-symbols). В проекте нет `keepDebugSymbols` для LibVLC. Поэтому эта разница **не объявляется дополнительной экономией APK**: требуется проверить упакованный файл.

В software-задачи debug/release добавлен `scripts/audit_libvlc_size.ps1`. JSON `libvlc-size-debug.json` или `libvlc-size-release.json` публикуется вместе с аудитом. Он показывает размеры внутри APK, сжатые размеры и оставшиеся отладочные секции. Шаг не меняет APK и не запускает сборку самостоятельно.

Повторить анализ существующего архива:

```powershell
pwsh -File scripts/audit_libvlc_size.ps1 -Archive <путь-к-aar-или-apk> -Report .tools/libvlc-size.json
```

## Почему нельзя удалить отдельные кодеки из AAR

В [официальном Android.mk](https://code.videolan.org/videolan/libvlcjni/-/blob/0b8dc65efb203c86a0476bc337ddd99ecf1c0ef6/libvlc/jni/Android.mk) VLC-модули и contrib-библиотеки статически объединяются в `libvlc.so`. В AAR нет отдельных `.so` для каждого кодека. Java/R8-оптимизация не вырезает встроенные нативные модули. Удалять `libc++_shared.so` нельзя: это зависимость `libvlc.so`, подтверждённая `DT_NEEDED`.

Проверены официальные исходники `libvlcjni-3.x`: commit `0b8dc65efb203c86a0476bc337ddd99ecf1c0ef6`, объявленная версия 3.7.7. Ресурсы AAR содержат `build_libvlc_revision=0b8dc65` и `build_vlc_revision=586dd059ac`.

Однако `buildsystem/get-vlc.sh` этого commit по умолчанию указывает другой VLC commit: `84177b2273abc5c4300234e6e18b55a4d2dd5a03`. Для воспроизведения исходного бинарника одного номера 3.7.7 недостаточно: нужно явно фиксировать также VLC revision, contribs и toolchain.

## Что требуется для просмотра

`CosmosFmp4Resolver` выбирает AV1-вариант HLS с init-map и `.m4s`/`.mp4` сегментами. Плееру нужны HTTP(S), adaptive/HLS и MP4 demux, программное видео- и аудиодекодирование, перемотка, SurfaceView/GLES и Android-аудиовывод. Сохраняются длительность, прогресс и события завершения.

На первом этапе не отключать AV1/dav1d, FFmpeg/avcodec/avformat, HTTP/TLS, HLS/adaptive, MP4, AAC/Opus и остальные аудиодекодеры, преобразование аудио/видео, Android outputs, JNI, события и seek. Реальные аудиокодеки всех потоков не проинвентаризированы. Отображение субтитров также сохраняется.

## Подготовленный экспериментальный профиль

`scripts/prepare_libvlc_tv_profile.ps1` меняет только чистую копию официальных исходников на закреплённом commit. Профиль отключает:

- Lua-плейлисты и метаданные;
- UPnP/mDNS-обнаружение, SMB/DSM/NFS;
- архивы, Blu-ray/DVD и RTSP/live555;
- исходящий стриминг/транскодирование (`sout`);
- MOD, игровые музыкальные форматы и MIDI-синтезатор FluidLite.

Эти возможности не используются текущим software-плеером. Входящий HTTP/HLS-стриминг и исходящий `sout` — разные подсистемы: отключается только вторая. Декодеры и необходимые компоненты намеренно не отключаются; работоспособность сокращённого бинарника ещё не проверена.

```powershell
pwsh -File scripts/prepare_libvlc_tv_profile.ps1 -SourceRoot <чистый-checkout-libvlcjni>
```

Скрипт проверяет commit, отсутствие изменений целевого файла и ожидаемые флаги; при несовпадении останавливается. Проверено применение на официальных исходниках: 18 замен флагов, Bash-синтаксис сохранён. Скрипт ничего не компилирует и не подменяет зависимость приложения.

## До включения в приложение

1. Получить JSON-аудит software APK из следующего обычного CI-запуска и проверить stripping C++ runtime.
2. Установить точную исходную VLC/contrib/toolchain-базу. Собрать контрольный и экспериментальный AAR в одинаковом окружении для ARMv7 и ARM64. Сравнить размеры и configure-отчёты: отключение contrib не всегда исключает альтернативный модуль.
3. Проверить на TV AV1 480p/720p/1080p, звук, длительность, паузу, перемотку, продолжение, смену качества, завершение и сетевые ошибки. Проверить минимальную версию Android и выравнивание ELF.
4. Подключать уменьшенный AAR после этих проверок. Экономия от профиля пока **не измерена**. Рабочее воспроизведение остаётся на официальном AAR.
