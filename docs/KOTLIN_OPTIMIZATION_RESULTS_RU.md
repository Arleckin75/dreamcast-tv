# Оптимизация Kotlin: изменения и проверки

Дата: 04.11.2026. Изменения поверх `ca9dfef`, без коммита и публикации.
Основание: [исходный аудит](KOTLIN_OPTIMIZATION_AUDIT_RU.md).

## Реализовано

| Область | Изменение |
| --- | --- |
| История | UI получает до 10 последних непросмотренных релизов отдельным SQL-запросом, полный прогресс — для релизов текущей навигации. Последняя просмотренная серия не заменяется более старой непросмотренной. Добавлены индексы по времени и релизу. |
| VLC-синхронизация | Только software-вариант. Сравниваются timestamps VLC и native, SQL читается для изменённых episode keys; полная SQL-история больше не материализуется для синхронизации. |
| Hardware lifecycle | Опрос панели прекращается при её скрытии и остановке Activity. Периодическое сохранение работает только при воспроизведении, учитывает PiP и пропускает одинаковые snapshots. Финальные сохранения остаются обязательными. Перед заменой идентификатора серии сохраняется предыдущая серия. |
| Software resolver | Отменяемая операция отключает HTTP, отменяет Future и удаляет отменённые задачи из очереди. Новый запрос и выход отменяют старую операцию; старый callback не доставляется. Ограничены два рабочих потока. Исправлено распознавание RESOLUTION в начале атрибутов HLS. |
| Software lifecycle | Воспроизведение приостанавливается до ухода Activity в фон. Разрешённый URL не запускает новый player без активной Activity/поверхности. При возвращении SurfaceView видеовывод повторно привязывается, ранее игравшая серия продолжается. Отложенное восстановление позиции не выполняется без поверхности. |
| Дисковый кэш | Фоновое обслуживание после первого UI-кадра и периодически при записи. Целевой бюджет — 512 записей / 16 МиБ payload; между пакетными очистками возможен небольшой временный выход за бюджет. Просроченный кэш сохраняется ещё до 7 суток для stale/offline fallback, если позволяет бюджет. Крупнейший ответ сверх бюджета используется без сохранения. Пользовательские таблицы не очищаются. |
| Запросы | Совпадающие одновременные загрузки объединяются. Отмена одного читателя не отменяет работу остальных; отмена всех отменяет операцию. Явный refresh отделён от обычной загрузки. Поиск с разными фильтрами имеет разные ключи. |
| Ожидание сети | До 12 с на HTTP call и 20 с на логическую операцию с retry. Постоянные HTTP-ошибки не повторяются; временные допускают до трёх попыток в общем бюджете. Внешняя отмена сохраняет прежнюю семантику. |
| Stale UI | Каталог, главная, фильтры, описание и расписание могут показать старые данные до завершения сетевого обновления. Промежуточная страница не фиксируется как завершённая пагинация. Политика свежести подписанных playback URL сохранена. |
| Ленты | Новые страницы разделяют неизменяемые блоки предыдущих карточек и ID-индексы. Карта всего каталога не строится заново при каждом append. Неактивные ленты вытесняются по общему бюджету 2048 карточки; активный каталог не обрезается. |
| Навигация | Состояния окончательно удалённых detail/episodes-маршрутов удаляются из SaveableStateHolder; состояния основных разделов и back stack сохраняются. |
| Preferences | Один снимок для чтения библиотеки, подписок и уведомлений в пределах refresh. Связанные записи закладки выполняются одним Editor. Пользовательская история уведомлений не удаляется. |
| Уведомления | Периодическая и одноразовая проверки используют общий mutex. Поиск выполняется партиями до двух запросов, с общим бюджетом 120 с. Курсор сохраняется по завершённым партиям; неизменившиеся подписки не перезаписываются. Проверяется, что пользователь не изменил подписку во время HTTP. |
| Release | Включены R8 и shrinkResources, добавлены keep rules для LibVLC JNI и имени WorkManager worker. |
| Метрики | Добавлены нативные debug-события первого UI-кадра, готовности главной, repository cache/network/stale и первого отображённого hardware-кадра; SQL/parse trace sections доступны отдельно. В событиях нет URL, поисковых строк или токенов. Первый UI-кадр регистрируется один раз за процесс. |
| CI | Hardware job выполняется независимо от LibVLC; software сохраняет зависимость от проверенного AAR. |

«Бессрочно» отключает возрастное истечение записей кэша, но не бюджет хранения. В настройках добавлено объяснение автоматической очистки. История просмотра, профиль и библиотека от обслуживания кэша не удаляются.

## Автоматические проверки

Финальная локальная команда:

```powershell
./android/gradlew.bat -p native-android :app:testHardwareAv1DebugUnitTest :app:testSoftwareAv1DebugUnitTest :app:lintHardwareAv1Debug :app:lintSoftwareAv1Debug :app:assembleHardwareAv1Release :app:assembleSoftwareAv1Release --console=plain
```

Результат: **BUILD SUCCESSFUL**.

- Hardware unit-тесты: **86**, ошибок и пропусков нет.
- Software unit-тесты: **87**, ошибок и пропусков нет. Большинство сценариев общие для двух вариантов.
- Новые проверки покрывают объединение загрузок, отмену одного/всех читателей, публикацию stale до HTTP-ответа, refresh, ключи фильтров, постоянные HTTP-ошибки, бюджеты кэша, ограниченные snapshots, многократную пагинацию, вытеснение неактивных лент, координацию worker и отмену resolver.
- Lint: hardware **0 ошибок / 49 предупреждений / 5 hints**, software **0 / 54 / 5**. Наличие предупреждений не скрывается; обновление всех зависимостей и устранение всех прежних предупреждений не входили в этот пакет.
- Оба release APK собраны с R8/resource shrinking: hardware **3 275 845 байт**, software **84 217 067 байт**. Это итоговые размеры, не измерение выигрыша относительно эквивалентной baseline-сборки.
- `scripts/audit_av1_apk.py` для обоих release APK: **PASS**. Проверены разделение движков, сохранение JNI-классов и уменьшенный ARM LibVLC.
- `actionlint .github/workflows/build-native.yml`: без замечаний. Удалённый GitHub Actions run не запускался.
- `git diff --check`: без ошибок пробелов.

Полные локальные журналы: `.tools/kotlin-optimization-final.log`, `.tools/kotlin-optimization-hardware-device.log`, `.tools/kotlin-optimization-software-device.log`, `.tools/kotlin-optimization-software-playback-device.log`, `.tools/kotlin-optimization-software-lifecycle-device.log`. Они исключены из Git.

## Проверки на физических устройствах

Приложения собраны с `-PnativeDebugSuffix=.optimizationTest`, установлены отдельно от пользовательской версии. После проверок оба временных приложения и их test APK удалены с обоих устройств; пользовательское приложение и его данные не заменялись.

| Устройство | Проверка | Результат |
| --- | --- | --- |
| Google TV Streamer, Android 14 / API 34 | Каталог, баннер, год и несколько жанров, библиотека, возврат | PASS |
| Google TV Streamer | Реальный Media3 pipeline на локальном PCM-файле: прогресс, пауза без повторных записей, качество, скорость, звук, перемотка, скрытие панели и выход | PASS |
| Cosmos / old ATV, Android 11 / API 30, ARMv7 | Каталог, фильтры, библиотека, возврат | PASS |
| Cosmos / old ATV | Реальный software AV1 1280×720, fMP4 HLS, сохранение позиции, уничтожение/воссоздание поверхности при уходе и возврате Activity, восстановление положительного Vout и движения позиции, выход через Back | PASS, последний целевой прогон 15,907 с |

Software fixture: собственный синтетический ролик длительностью 30 с, 5 fps, без звука. Он проверяет decoder/renderer и lifecycle, но не является нагрузочным тестом обычного 24/30 fps видео.

Первичные прогоны выявили неточные селекторы/синхронизацию прежних UI-тестов. Выбор года ограничен диалогом, checkbox проверяется на включение, «Применить» нажимается через D-pad, hardware-тест дожидается полного появления панели.

Отдельная проблема тестовой среды: Google TV через HDMI-CEC перехватывал вход Cosmos. Это прерывало тесты и в одном прогоне сопровождалось падением Mali/AWindowHandler при уничтожении Surface. После этого добавлена защита software lifecycle, а уничтожение/возврат SurfaceView проверены отдельным целевым тестом. Для финального software-прогона CEC на Streamer временно отключался; после проверки **hdmi_cec_enabled восстановлен в 1**, Streamer разбужен. Приложение не блокирует внешнее переключение HDMI; финальная проверка воспроизводит уход/возврат Activity программно, а не всю цепочку CEC.

Один промежуточный повтор каталога на Cosmos оборвался внутри Compose accessibility (`performMeasureAndLayout called during measure layout`). Другие прогоны этого сценария прошли. Версии Compose не менялись; этот редкий framework-сбой не объявляется устранённым. Последний целевой software-прогон запускался отдельно от Compose-тестов и прошёл полностью.

## Границы результата

Проверки не обнаружили регрессий в перечисленных финальных сценариях. Это не доказательство отсутствия любых ошибок.

- На TV выполнялись debug instrumentation-сборки. Оптимизированные release APK проверены сборкой и аудитом состава, но не запускались на устройствах; локальная подпись production отсутствует, APK unsigned.
- Длительный playback, PiP, аварийное завершение процесса и сетевые сбои на физических TV не проверялись исчерпывающе. Сохранение/отмена/refresh дополнительно покрыты локальными регрессионными тестами.
- Численного сравнения производительности до/после, frame timings и длительного PSS/native heap профиля нет; процент ускорения не заявляется.
- Custom baseline profile, собственный ImageLoader, миграция коллекций preferences в SQL и изменение decoder/буферов остаются условными кандидатами после профилирования, а не автоматически выполненными «исправлениями».
- Последовательные обращения к repository по-прежнему проверяют SQLite. Межзапросный raw memory cache намеренно не добавлен: он потребовал бы отдельной гарантии invalidation для clear/retention и внешних записей. Исправлено дублирование именно одновременных загрузок.
- Активный каталог может содержать все загруженные страницы. Лимит применяется к неактивным лентам, чтобы оптимизация не скрывала доступные релизы.

## Повторение device-проверок

```powershell
./android/gradlew.bat -p native-android '-PnativeDebugSuffix=.optimizationTest' :app:assembleHardwareAv1Debug :app:assembleHardwareAv1DebugAndroidTest :app:assembleSoftwareAv1Debug :app:assembleSoftwareAv1DebugAndroidTest
```

Установить APK нужного flavor и его androidTest APK на соответствующее устройство, затем выполнить:

```text
adb -s SERIAL shell am instrument -w com.dreamcast.app.optimizationTest.test/androidx.test.runner.AndroidJUnitRunner
```

Два flavor имеют один applicationId и проверяются на разных устройствах либо устанавливаются последовательно. Перед software-проверкой исключить внешнее переключение HDMI-входа. Не смешивать журналы первичных неудачных прогонов с финальными результатами.
