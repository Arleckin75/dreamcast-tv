# Cosmos HLS diagnostics (develop / Debug only)

Добавлен анализатор `DCTV_HLS` в `CosmosHlsDiagnostic.kt`.

При открытии LibVLC автоматически проверяется исходный HLS-плейлист и до двух вариантов с наименьшим BANDWIDTH. Проверяются тип (master/media), CODECS, RESOLUTION, BANDWIDTH, наличие EXT-X-MAP, ключей шифрования, LL-HLS PART, форматы ссылок на сегменты и HTTP content type/status.

Анализатор не загружает видеосегменты и не записывает URL, пути, query-параметры, токены, ключи или содержимое плейлистов в logcat. Использует User-Agent/Referer из потока. Проверка не меняет основное воспроизведение. Данные об extension описывают окончания ссылок на сегменты, а не фактически проверенное содержимое видео.

Получить лог в Windows PowerShell:

```powershell
& "D:\adb\adb.exe" -s 192.168.0.9:5555 logcat -c
# Затем запустить серию, дождаться 15 секунд
& "D:\adb\adb.exe" -s 192.168.0.9:5555 logcat -d -v threadtime -s DCTV_HLS:I DCTV_AV1:I | Out-File "$HOME\Desktop\cosmos-hls.txt" -Encoding utf8
```

Ограничения: HTTP-заголовки аутентификации помимо User-Agent и Referer не передаются в исходный LibVLC и в этот анализатор. Если сервер требует другие заголовки или URL недолговечен, диагностика может получить HTTP 401/403, что не следует трактовать как отсутствие AV1-декодера. Сегменты не читаются; тип контейнера выводится по плейлисту и расширениям ссылок.

Стабильную v0.6.0 и Release не изменять. Сборка APK в этой среде не выполнялась.
