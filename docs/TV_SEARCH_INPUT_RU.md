# Системный ввод поиска на Cosmos

03.11.2026 воспроизведён дефект установленной software AV1 на Cosmos через ADB:
Gboard показан (`mInputShown=true`), но стрелка вниз с источником D-pad не меняет
выделение буквы `q`. На том же устройстве в системном приложении «Поиск» такое
же нажатие переместило выделение с `g` на `b`.

Обе программы используют выбранный системный IME
`com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME`
(Gboard). Отличаются параметры редактора и обработка событий ввода:

| Поле | Dreamcast до изменения | Системный поиск |
|---|---|---|
| inputType | `0x8001` | `0x1` |
| imeOptions | `0x2000003` | `0x8000003` |
| privateImeOptions | отсутствуют | `noDecoding`, `noMicrophoneKey` Gboard |

У плавающей клавиатуры видимые нижние отступы равны нулю, поэтому проверка только
Flutter viewInsets не подтверждает отсутствие IME. Предыдущие widget-тесты
проверяли запрос открытия, но не реальную навигацию по буквам Gboard.

Для software AV1 набор текста перенесён в нативный Android EditText в верхнем
окне ввода. Оно вызывает текущий системный IME с параметрами, снятыми с рабочего
системного поиска. Пульт во время набора обрабатывается Android, без Flutter
TextField/Shortcuts. Back закрывает редактор и возвращает набранный текст в поиск;
действие поиска на клавиатуре дополнительно отправляет запрос. Повторное открытие
сохраняет текст. Окно использует цвета темы приложения. Встроенной клавиатуры нет,
настройки выбранного IME не меняются. Hardware AV1 сохраняет Flutter-ввод.

Локальный тест software проверяет вызов нативного канала, сохранение текста и
безопасное завершение после ухода с экрана; обычные тесты проверяют старый
hardware-путь. Новый нативный путь необходимо проверить после пересборки на TV:
движение выделения по буквам, ввод, поиск, Back, повторное открытие, переход к
результатам и возврат вверх. Результат исправления на устройстве пока не подтверждён.

Снимки сравнения сохранены локально в `.tools/search-ime-*.png` и
`.tools/native-search-*.png`, в Git не входят.
