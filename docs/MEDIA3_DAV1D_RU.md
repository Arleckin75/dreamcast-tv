# Выбор декодирования в едином APK

Плеер основан на прежнем hardware-плеере Media3 1.9.2. Один APK для ARMv7 и
ARM64 включает dav1d 1.5.1 и cpu_features 0.10.1. Сборка: [BUILD_TV.md](../BUILD_TV.md).

## Настройки плеера → Декодирование

- **Авто**: подходящий аппаратный MediaCodec предпочтителен. Если аппаратного
  AV1 нет, применяется dav1d. Для других кодеков сохраняются системные декодеры.
- **Аппаратное**: доступно только при наличии аппаратного MediaCodec,
  поддерживающего параметры текущего видео. Иначе пункт серый и не активируется.
- **Программное AV1 — dav1d**: использует только dav1d для видео; недоступно для
  других кодеков и неподдерживаемого защищённого AV1.

Режим сохраняется в `player.decoder_mode`. Если сохранённый принудительный
режим не подходит новому потоку, плеер использует «Авто». Смена режима сохраняет
позицию, паузу, скорость и выбор качества.

MetadataRetriever читает форматы с теми же HTTP-заголовками, что и плеер.
До старта видеовывода проверяются MIME, профиль/уровень, размер и частота кадров
через Media3 MediaCodecInfo. Для аппаратного режима исключены softwareOnly-кодеки.
На API ниже 29 Media3 определяет аппаратный признак по совместимым эвристикам;
на новых API доступен системный аппаратный флаг.

Аппаратному пути предоставляется обычный PlayerView. dav1d получает
`video_decoder_gl_surface_view`, необходимый для устойчивого возврата из фона
на Cosmos. В «Авто» качества dav1d предпочитает видео до 720p для старых устройств.
Очереди ввода и вывода dav1d увеличены до 12 буферов для сглаживания скачков времени
декодирования. Число потоков и задержку между кадрами выбирает dav1d.
Если в двух последовательных пятисекундных окнах теряется не менее 5% кадров
(минимум 6 потерянных и 50 обработанных за окно), качество «Авто» ограничивается
следующим меньшим доступным AV1-разрешением до переоткрытия потока или ручного
выбора качества. Пауза, перемотка и буферизация сбрасывают накопленные измерения.
Ручное качество не понижается автоматически. Журнал `DCTV_DECODER` содержит
фактический входной формат, пропуски кадров и причину автоматического снижения.
HDR и 10-битный GL-вывод требуют отдельной проверки на целевых потоках.

## Ошибки и жизненный цикл

В режиме «Авто» ошибка аппаратного видеорендерера для поддерживаемого AV1
перезапускает тот же поток через dav1d один раз с сохранением позиции.
Ошибки сети и аудио не вызывают такой переход. Во время чтения метаданных
отменяются устаревшие операции; поздние результаты не заменяют новый поток.
Пауза и фон сохраняют состояние, PiP остаётся частью общего плеера.

Диагностика: `DCTV_DECODER` содержит запрошенный режим, путь вывода и имя
фактического декодера; `DCTV_PERF` — время первого кадра.

Повторные замеры плавности и проверенные эксперименты описаны в
[отчёте по Cosmos](COSMOS_FRAME_PACING_RU.md).
